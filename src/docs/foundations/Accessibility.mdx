# Accessibility

Every component targets **WCAG 2.1 level AA in both themes**.

## The bar

- Text contrast is at least 4.5:1 (3:1 for large text). Control borders, focus rings and meaningful icons are at least 3:1.
- Everything is keyboard operable, with a visible `:focus-visible` ring in the accent color.
- Roles, names and states are correct: `aria-pressed`, `aria-expanded`, `aria-selected`, `aria-current`, live regions.
- Color is never the only signal. A done row also shows a check and a hidden "Done" label; negative money also has a minus sign. In Windows High Contrast (forced colors), state falls back to system colors.
- Visible labels are part of the accessible name (WCAG 2.5.3 Label in Name).
- `prefers-reduced-motion` turns off animation.
- Layouts reflow at 320px width and at 200% zoom.
- Touch targets are at least 44 by 44px, beyond what AA requires.

## How it is enforced

- **axe on every story, in both themes.** The Storybook a11y addon runs axe on each story and the test runner fails on any violation (`a11y.test = 'error'`). Because every component has a `Dark` story, both themes are covered.
- **Contrast unit tests.** Every documented foreground and background token pair is checked in both themes. The Colors page shows the same numbers live.
- **Play functions** exercise keyboard interaction, roles and states.
- **Viewport tests** cover reflow, touch hit areas and forced colors in a real browser.

Automated checks catch a fraction of problems, so the interaction patterns are also designed up front around
native semantics.

## Radix for the hard parts

Where correct accessible behavior is genuinely difficult, Perch UI uses Radix UI primitives: Dialog (Sheet),
Popover (Toggletip), Toast, Select, and Tabs (Tabs and SegmentedControl). They handle focus management, typeahead,
dismissal and ARIA wiring. Everything else is hand-built on native elements.
